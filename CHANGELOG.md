# Changelog

Все значимые изменения в проекте light_nmea.

## [2.3.0] - 2026-08-09

### Добавил
- Lookup-таблицу `_HEX_VALUE` для быстрой проверки CRC
- 24-битные идентификаторы типов сообщений (`_MSG_ID_RMC`, `_MSG_ID_GGA`, `_MSG_ID_VTG`, `_MSG_ID_GLL`)
- 16-битные константы Talker ID для NMEA v4.10+ (`_TALKER_ID_BD`, `_TALKER_ID_QZ`, `_TALKER_ID_IR`)

### Технические детали
- Все декораторы `@native` и `@viper` являются опциональными - код работает в чистом интерпретаторе MicroPython без потери функциональности

### Изменил
- **`parse_line()`**: быстрый фильтр по созвездию и типу сообщения **до** копирования в буфер - отсечение мусорных пакетов
- **`_scan_line()`**: однопроходный сканер с ранним выходом при нахождении `*`, проверка CRC через таблицу HEX
- **`_get_constellation()`**: определение созвездия через lookup-таблицу вместо цикла сравнений
- **`_parse_rmc()`**: локализация `self._comma_pos` в переменную `cp`, убрал повторные attribute lookups
- **`_parse_gga()`**: локализация пере…*: 494 pkt/s при 176 байт RAM на пакет
- **CPython (3.9 GHz)**: 109,453 pkt/s
- **В 22.6 раза быстрее** micropyGPS на RP2040
- **В 2.8 раза быстрее** micropyGPS на CPython
- **В 1.4 раза быстрее** adafruit_gps на CPython
- **В 1.3 раза быстрее** pynmea2 на CPython
- **В 2.1 раза быстрее** pynmeagps на CPython
- **В 1.7 раза быстрее** vihasnaps на CPython
- Удельная эффективность: **27.93 пакетов/MHz** (против 20.18 у adafruit_gps)
- 100% успешно обработанных пакетов в тестах (333,333 из 333,333)

## [2.2.0] - 2026-07-30

### Добавил
- Функцию `get_ublox_hardware_status()` для мониторинга RF-части u-blox M10
- Поддержку аппаратного сброса GNSS-модуля через GPIO-пин (`reset_pin`)
- Окна `PositionWindow`, `GNSSWindow`, `MotionWindow` с анализом точности по алгоритму Уэлфорда
- Логирование GNSS-данных в `gnss_log.csv` с timestamp
- Обработку системных сообщений `SYS_MSG` от MicroPython-платы
- Проверку минимального размера терминала для curses-дашборда
- Защиту от перехвата порта другими программами (Thonny, screen)

### Изменил
- Вынес утилиты GNSS в отдельный пакет `gnss_module_utils`
- Перенаправил `stderr` в `mcu_debug.log`

## [2.1.0] - 2026-07-23

### Добавил
- Базовый интерфейс `IGNSSParser` для унификации API всех GNSS-парсеров
- Методы интерфейса: `is_valid()`, `get_constellation()`, `parse_line()`, `reset()`
- Константа `INTERFACE_VERSION = 0b0001_0001` для проверки совместимости
- Экспорт `IGNSSParser` в `__init__.py` для удобства расширения
- Поддержка парсинга координат из GGA через унифицированный метод `_parse_coordinates`

### Изменил
- `NMEAStreamReader` теперь типизирован и использует методы интерфе…акт (добавлены методы-обертки `is_valid()`, `get_constellation()`)
- Упрощена логика `reset()` - единый метод сброса всех состояний
- Улучшена точность бенчмарка памяти: переход с `gc.mem_free()` на `gc.mem_alloc()` для исключения влияния фрагментации кучи

### Производительность
- **23.8x** быстрее micropyGPS на RP2040 (502 pkt/s против 21 pkt/s)

## [2.0.0] - 2026-07-12

### Добавлено
- Поддержка VTG (Track Made Good and Ground Speed)
- Поддержка GLL (Geographic Position)
- Поддержка VTG без Mode Indicator (старый формат NMEA)
- Диагностика по типам сообщений
- Модуль `conv_to_hrf` с функциями форматирования: `_to_txt`, `_to_csv`, `_to_json`, `_to_compact`
- Функция `to_format()` и константы форматов (`FMT_TXT`, `FMT_CSV`, `FMT_JSON`, `FMT_COMPACT`)
- Форматирование времени и даты через `_fmt_dt()` с поддержкой `bytes` и `str`

### Изменено
- `parse_line` разбит на отдельные методы: `_parse_rmc`, `_parse_gga`, `_parse_vtg`, `_parse_gll`
- GLL при статусе 'V' сбрасывает только координаты, не трогая данные из других сообщений
- Один `memoryview` для всех полей GGA (вместо нескольких)
- Сборка CSV-строк переведена на `",".join()` для корректного парсинга в MicroPython
- Все магические строки, числа и идентификаторы вынесены в константы модуля

### Исправлено
- Критическая ошибка `TypeError` при сравнении полей `NoneType` с `int` (HDOP, созвездие, режим фикса) до получения полного пакета GGA
- Ошибка `SyntaxError` в MicroPython при использовании многострочных f-строк
- Ошибка `TypeError: join expects a list of str/bytes` в `_to_csv` (добавлено явное приведение типов)
- Некорректный вывод `None` в текстовых и JSON форматах (теперь возвращаются пустые строки или дефолтные значения)
