# LightNMEA

Экстремально быстрый, независимый от внешних библиотек NMEA 0183 парсер с минимальным выделением памяти, 
написанный специально для MicroPython и Python (CPython).

Разработан для 32-разрядных микроконтроллеров (ESP32, STM32, RP2040), 
работающих с высокочастотными GNSS-приемниками (10-50 Гц. Мультисистемные GPS/ГЛОНАСС/BeiDou/Galileo модули).

##  Почему light_nmea?
На момент создания (июнь 2026) для MicroPython существовал только один NMEA-парсер - micropyGPS (2018 год). Он работает, но медленно (25 п/с) и не поддерживает современные созвездия GNSS.
light_nmea создан как альтернатива:

      ×15 быстрее micropyGPS
      Поддержка семи созвездий (GPS, ГЛОНАСС, Galileo, BeiDou, QZSS, NavIC, Multi)
      Нулевое выделение памяти в цикле обработки
      Интеграция с RTC MCU (MicroPython)
      Не блокирующее потоковое чтение UART

Другие популярные парсеры (pynmea2, pynmeagps) не работают на MicroPython из-за зависимостей от CPython модулей (dataclasses, typing).

## Производительность

Большинство NMEA-библиотек для Python написаны "в лоб": они активно используют 
`string.split(b',')`, регулярные выражения или создают сотни мелких подстрок 
`bytes` на каждый пакет. На микроконтроллерах это приводит к мгновенной 
фрагментации кучи (heap), регулярным фризам сборщика мусора (`gc.collect()`) 
и, как следствие, к переполнению буфера UART и потере пакетов.

`LightNMEA` решает эту проблему благодаря однопроходному сканированию буфера 
с предварительно выделенным трекером позиций, табличному lookup созвездий 
и использованию `@native`-декораторов MicroPython для основного пути.

### Методика тестирования

Чтобы гарантировать честное и объективное сравнение, скрипт бенчмарка реализует следующие условия:
* **Реальная нагрузка**: Тесты выполняются на репрезентативном потоке от 300 000 до 1 000 000 пакетов NMEA 0183 (включая стандартные сообщения `RMC` и `GGA`).
* **Фаза прогрева**: Каждый парсер проходит фазу прогрева (2 полных прогона) перед фактическим замером, чтобы исключить накладные расходы на инициализацию интерпретатора.
* **Проверка доступа к свойствам**: Бенчмарк не просто вызывает функцию парсинга; он выполняет обязательное обращение к свойствам (`_ = gps.valid` и `_ = gps.latitude`), что заставляет код выполнять полное декодирование и валидацию данных.
* **Лучший из 3**: Итоговые результаты основаны на минимальном затраченном времени за 3 независимых прогона, что предотвращает влияние случайных всплесков нагрузки ОС на результаты.
* **Сборка мусора**: Перед каждым запуском принудительно вызывается `gc.collect()`, чтобы гарантировать точное базовое состояние памяти.

### Без выделения ОЗУ на основном пути

Основной цикл парсинга (`parse_line`) не создаёт новых объектов в памяти:

- Позиции запятых хранятся в предварительно выделенном `bytearray`
- Сравнения типов сообщений (`RMC`, `GGA`) и статусов (`A`, `S`, `W`) 
  выполняются через целочисленные ASCII-коды, а не через срезы `bytes`
- CRC-проверка встроена в однопроходный сканер - без отдельных вызовов
- Определение созвездия GNSS - табличный lookup по ASCII-кодам

Аллокации происходят только для сохранения конечных значений 
(`latitude`, `longitude`, `speed`, `course`, `altitude`, `time`, `date`) - 
это неизбежно, так как пользователь должен получить их как независимые 
объекты. Но сам процесс парсинга **не засоряет кучу**, что критично 
для MicroPython с его малым объёмом RAM и дорогим сборщиком мусора.

### Запас по скорости для GPS-приложений

| Частота GPS             | Пакетов/сек | Запас на MicroPython |
|-------------------------|-------------|----------------------|
| 1 Гц (стандарт)         | 1           | ×375                 |
| 5 Гц (быстрый)          | 5           | ×75                  |
| 10 Гц (высокочастотный) | 10          | ×37                  |

Даже при частоте 20 Гц у микроконтроллера остаётся **×18 запаса** по CPU 
для другой логики приложения (отрисовка дисплея, связь, журналирование).

## Ключевые архитектурные оптимизации

1. **Однопроходный сканер.** За один проход по байтам строки вычисляет 
   контрольную сумму (XOR), находит границы полезной нагрузки (`*`) и 
   записывает индексы всех запятых-разделителей (`,`) в предварительно 
   выделенный массив `bytearray`.

2. **Инлайновый разбор данных.** Логика извлечения полей полностью развернута 
   внутри основного цикла. Все границы полей рассчитываются на месте по 
   готовым индексам, что устраняет накладные расходы на создание фреймов 
   стека и лишние вызовы функций.

3. **Защита от фризов GC.** Извлечение и перевод координат, скорости и курса 
   в числа происходит "на лету" без генерации промежуточного строкового 
   мусора в куче.

## Быстрый старт (Пример использования на RP2040)
```python
from light_nmea import LightNMEA

# Инициализация парсера
parser = LightNMEA(trust_gga_fix=True)

# Сырая строка байт из UART или лог-файла
raw_sentence = b"$GNRMC,091530,A,5575.2057,N,03762.6130,E,15.0,120.5,220626,,,A*7F"

# Парсинг строки
if parser.parse_line(raw_sentence):
    if parser.valid:
        print("Широта:  ", parser.latitude)
        print("Долгота: ", parser.longitude)
        print("Скорость:", parser.speed, "км/ч")
        print("Время:   ", parser.time.decode('ascii'))
```
## Пример использования (поток пакетов)
```python
from light_nmea import LightNMEA

parser = LightNMEA(trust_gga_fix=True)

# Имитация потока данных из лога или UART
stream_packets = [
    b"$GNRMC,091530,A,5575.2057,N,03762.6130,E,15.0,120.5,220626,,,A*7F",
    b"$GNGGA,091530,5575.2057,N,03762.6130,E,1,12,1.0,156.3,M,0.0,M,,*42"
]

for raw_sentence in stream_packets:
    if parser.parse_line(raw_sentence):
        print("--- Пакет успешно обработан ---")
        print("Статус фикса:", parser.valid)
        print("Время UTC:   ", parser.time.decode('ascii') if parser.time else "Нет")
        
        if parser.has_coordinates():
            print("Координаты:", parser.latitude, ",", parser.longitude)
            
        if parser.has_navigation():
            print("2D навигация:", parser.speed, "км/ч,", parser.course, "град.")
            
        if parser.has_3d_fix():
            print("3D фикс:", parser.altitude, "метров")
            
        print("Спутники:", parser.satellites)
```

## Пример для MicroPython (RP2040 + UART)
```python
import gc
import time
from machine import UART, Pin, RTC
from light_nmea import LightNMEA

# Настройка UART
uart = UART(1, baudrate=9600, rx=Pin(5), rxbuf=512)
parser = LightNMEA(trust_gga_fix=True)
rtc = RTC()

# Критично для стабильной работы на MCU:
gc.threshold(8192)  # Автоматический GC при нехватке памяти

gc_counter = 0
rtc_synced = False

while True:
    if uart.any():
        raw_line = uart.readline()
        if raw_line and len(raw_line) > 10:
            if parser.parse_line(raw_line):
                if parser.has_coordinates() and not rtc_synced:
                    # Синхронизация RTC при первом фиксе
                    t = parser.time.decode()
                    d = parser.date.decode()
                    rtc.datetime((
                        # формат даты DDMMYY(!), вот почему + 2000!
                        2000 + int(d[4:6]), int(d[2:4]), int(d[0:2]), 0,
                        int(t[0:2]), int(t[2:4]), int(t[4:6]), 0
                    ))
                    rtc_synced = True
                
                # Периодический GC каждые 500 пакетов
                gc_counter += 1
                if gc_counter >= 500:
                    gc.collect()
                    gc_counter = 0
    
    time.sleep_ms(10)
```

## Справочник API
### Свойства
* `parser.valid` (`bool`): Флаг достоверности решения (True = фикс есть, False = нет).
* `parser.latitude` (`float | None`): Широта в градусах (WGS84, диапазон от -90.0 до +90.0).
* `parser.longitude` (`float | None`): Долгота в градусах (WGS84, диапазон от -180.0 до +180.0).
* `parser.speed` (`float | None`): Скорость движения. Автоматически переведена в км/ч.
* `parser.course` (`float | None`): Истинный курс (путевой угол) в градусах относительно географического севера (0.0 - 359.9).
* `parser.altitude` (`float | None`): Высота над средним уровнем моря (геоидом) в метрах.
* `parser.satellites` (`int`): Количество используемых в решении спутников.
* `parser.time` (`bytes`): UTC-байты времени (формат HHMMSS).
* `parser.date` (`bytes`): UTC-байты даты (формат DDMMYY).

### Методы проверки состояния

* `parser.has_coordinates() -> bool`: True, если и широта, и долгота распарсены и не равны None.
* `parser.has_navigation() -> bool`: True, если доступны валидные координаты, а также параметры скорости и курса (полноценный 2D-фикс).
* `parser.has_3d_fix() -> bool`: True, если помимо плановых координат доступна информация о высоте над уровнем моря (полноценный 3D-фикс из GGA).

### Мониторинг ОЗУ (Класс GPSStats)

Для контроля состояния оперативной памяти используется метод `stats.get_memory_usage() -> float`, который возвращает количество занятых килобайт.
* Под MicroPython он автоматически вызывает `gc.collect()` для получения реального объема кучи (Heap).
* Под Windows и Linux опрашивает интерфейсы операционной системы без использования внешних библиотек.

## Анти-спам фильтр

GNSS-приёмники могут отправлять дублирующиеся пакеты на высокой частоте (5-10 Гц и более). 
`NMEAStreamReader` имеет встроенный ограничитель частоты, который фильтрует избыточные 
пакеты GGA/RMC до того, как они попадут в парсер, снижая нагрузку на CPU микроконтроллера.

Эта функция особенно полезна при работе с высокочастотными GNSS-модулями, которые 
отправляют одни и те же данные несколько раз в секунду, позволяя обрабатывать только 
уникальные обновления без потери точности навигации.

### Как это работает

Фильтр работает на уровне стрим-ридера, **до** того, как пакеты попадут в парсер:

1. **Независимое отслеживание** — пакеты GGA и RMC отслеживаются раздельно. Отфильтрованный GGA не влияет на приём RMC, и наоборот.

2. **Фильтрация по времени** — для каждого типа пакета ведётся своя временная метка. Если новый пакет того же типа приходит в пределах настроенного интервала, он молча отбрасывается.

3. **Неизвестные сообщения проходят без фильтра** — пакеты типов, отличных от GGA/RMC (GSV, GSA, VTG и т.д.), всегда передаются парсеру без изменений. Фильтр их не затрагивает.

4. **Zero-allocation** — реализация использует `time.ticks_ms()` на MicroPython и `time.monotonic()` на CPython. При фильтрации не создаются строки, списки или объекты в куче.

Пример временной шкалы с интервалом 100 мс:

| Время  | Пакет | Действие                       |
|--------|-------|--------------------------------|
| 0 мс   | GGA   | Принят                         |
| 3 мс   | RMC   | Принят (другой тип)            |
| 50 мс  | GGA   | Отброшен (прошло только 50 мс) |
| 100 мс | GGA   | Принят (прошло 100 мс)         |
| 103 мс | RMC   | Принят (другой тип)            |

### Использование

```python
from light_nmea import LightNMEA, NMEAStreamReader

reader = NMEAStreamReader(uart)
parser = LightNMEA()

# Включаем анти-спам фильтр: минимум 100мс между пакетами одного типа
reader.set_anti_spam_interval(100)

while True:
    packets = reader.read_available(parser)
    if packets > 0 and parser.valid:
        print(f"Широта: {parser.latitude}, Долгота: {parser.longitude}")
```        
* Чтобы отключить фильтр, передайте 0 или None:
```python
reader.set_anti_spam_interval(0)  # Все пакеты будут переданы парсеру
```

### Настройка

Интервал фильтра задаётся через `set_anti_spam_interval(interval_ms)`.

| Интервал       | Поведение                                                                         |
|----------------|-----------------------------------------------------------------------------------|
| `0` или `None` | Фильтр отключён -- все пакеты передаются парсеру                                  |
| `100`          | По умолчанию для высокочастотных приёмников -- отбрасывает дубликаты в окне 100мс |
| `500`          | Умеренная фильтрация -- подходит для приёмников 2-5 Гц                            |
| `1000`         | Агрессивная фильтрация -- один пакет в секунду на каждый тип                      |

Допустимый диапазон: от `0` до `1000` миллисекунд. Значения вне этого диапазона вызывают `ValueError`.

**Как выбрать правильный интервал:**

- Для **приёмников 1 Гц** (стандартные GPS-модули): используйте `0` (отключено) -- фильтрация не нужна
- Для **приёмников 5-10 Гц** (высокочастотные модули): используйте `100-200` -- сохраняет одно обновление за 100-200мс
- Для **энергосберегающих приложений**: используйте `500-1000` -- значительно сокращает пробуждения CPU

### Когда использовать

- Высокочастотные GNSS-приемники (5-10 Гц и более), отправляющие дубликаты GGA/RMC.
- Снижение нагрузки на CPU и экономия энергии на микроконтроллерах.
- Защита от спама парсера, когда для логики приложения нужны обновления только 1 раз в секунду.

### Когда НЕ использовать

- Стандартные приемники 1 Гц (фильтрация не нужна и создает минимальные накладные расходы).
- Пост-обработка NMEA-логов (используйте парсер напрямую, минуя стрим-ридер).
- Приложения, требующие каждого сырого пакета для точного тайминга, RTK базовых станций или логирования сырых данных.

### Диагностика и сброс

Стрим-ридер ведет внутренний подсчет пакетов, отброшенных анти-спам фильтром. Это полезно для отладки и точной настройки интервала под ваше конкретное оборудование.

```python
print(f"Отброшено фильтром: {reader._anti_spam_dropped}") 
```
Если GNSS-модуль терял питание или вы изменили скорость UART во время работы, следует сбросить состояние стрим-ридера. Это очистит курсор внутреннего буфера, все статистические счетчики и временные метки анти-спам фильтра, гарантируя, что первый пакет после восстановления связи будет принят без задержек.
```python
reader.reset()
```

## Модуль потокового чтения (nmea0183_stream.py)
Модуль nmea0183_stream реализует неблокирующее чтение UART с кольцевым буфером и автоматическим извлечением полных NMEA-пакетов. Он решает главную проблему при работе с GPS-модулями на микроконтроллерах: потерю пакетов из-за переполнения буфера UART.

### Назначение

* Чтение байтов из UART без блокировки основного цикла приложения
* Накопление данных в кольцевом буфере (ring buffer) фиксированного размера
* Извлечение полных пакетов (от $ до \r\n) с встроенной проверкой CRC
* Передача готовых пакетов парсеру LightNMEA
* Работа в совместном режиме с time.sleep_ms() и gc.collect()

### Класс NMEAStream (Потоковое чтение UART)

* `NMEAStream(uart, buffer_size=512)`: Конструктор. Принимает объект `machine.UART` и размер кольцевого буфера в байтах (по умолчанию 512).

#### Методы

* `read_available() -> int`: Читает все доступные байты из аппаратного буфера UART в кольцевой буфер. Не блокирует выполнение. Возвращает количество прочитанных байт.
* `get_packet() -> bytes | None`: Извлекает следующий полный и валидный NMEA-пакет (с проверкой CRC) из буфера. Возвращает `bytes` или `None`, если пакет неполный или битый.
* `buffer_usage() -> int`: Возвращает текущее количество байт, занятых в кольцевом буфере (от 0 до `buffer_size`). Полезно для мониторинга переполнения.
* `reset() -> None`: Принудительно очищает кольцевой буфер и сбрасывает состояние поиска фрейма. Используется при критическом переполнении.
