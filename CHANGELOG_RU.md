# Changelog

Все значимые изменения в проекте light_nmea.

## [2.5.0] - 22.09.2026

### Исправил
- **Парсер. Повышена устойчивость к неверным числовым полям:** Добавил вспомогательные функции уровня модуля `_to_float()` и `_to_int()` с декоратором `@native` и обработкой исключений `try/except (ValueError, TypeError)`. Теперь преобразования чисел в методах `_parse_rmc` (скорость, курс), `_parse_gga` (качество фиксации, спутники, HDOP, высота) и `_parse_vtg` (курс, скорость в узлах/км/ч) защищены от сбоев: ранее пакет с верной контрольной суммой, но содержащий нечисловое поле (например, `abc` вместо скорости), вызывал исключение `ValueError` и аварийную остановку основного цикла обработки. Теперь при обнаружении поврежденного поля возвращается `None` или `0`, а разбор остальной части пакета продолжается.
- **Парсер. Привел таблицы режимов фиксации в соответствие со стандартом NMEA-0183:**
- `_FIX_MODE_TABLE` (поле 12 сообщения RMC сентенции, индикатор режима FAA): `'F'` -> `FIX_RTK_FLOAT`, `'R'` -> `FIX_RTK_FIXED` (RTK Integer) — ранее эти значения были перепутаны; `'P'` (Precise) теперь соответствует `FIX_RTK_FIXED`. 
- `_GGA_QUALITY_FIX_MODE` (поле 6 сентенции GGA): расширил диапазон с 0–5 до 0–8 — добавил значения `6` (Estimated -> `FIX_ESTIMATED`), `7` (Manual input -> `FIX_NOT_VALID`), `8` (Simulation -> `FIX_NOT_VALID`); значение `3` (PPS) теперь соответствует `FIX_AUTONOMOUS` (ранее — `FIX_NOT_VALID`).
- **Дашборд. `show_msg()`:** Исправил порядок аргументов `y`/`x` в вызове `curses.addstr()` — теперь предупреждение "Terminal too small" ("Терминал слишком мал") отображается в правильном месте.
- **Дашборд. Анализ точности:** `AccuracyTracker` теперь учитывает только реальные фиксы GNSS (`_VALID_FIX_MODES`: Autonomous, DGPS, RTK Fixed, RTK Float) — статусы `Unknown` и `Estimated` больше не считаются верными, поэтому процент успешных фиксов отражает реальную картину.
- **Дашборд. Буфер последовательного порта:** В метод `SerialParser.poll()` добавлено ограничение `_MAX_BUFFER_SIZE` (4096) — теперь поток байтов без символа `\n` (мусор в UART) не может привести к бесконечному росту буфера.

### Изменил
- **Парсер.** Устранил избыточное выделение памяти под `memoryview` в методах `_parse_rmc` и `_parse_vtg` — срезы теперь создаются однократно для каждого поля с помощью вспомогательных функций `_to_float` и `_to_int`.
- **Парсер.** Обновил комментарии к константам `FIX_*` в соответствии со стандартными буквенными обозначениями (`'R'`/`'P'` -> `FIX_RTK_FIXED`, `'F'` -> `FIX_RTK_FLOAT`).

### Добавил
- **Генератор тестовых пакетов (`nav_gen.py`):** Добавил 7 новых пакетов (индексы 24–30) с неверными числовыми полями, но верными контрольными суммами: скорость RMC `xyz`, курс RMC `abc`, HDOP GGA `abc`, спутники GGA `xx`, высота GGA `15x.3`, скорость VTG (км/ч) `4.72x`, курс VTG `08x.4`. Они проходят проверку CRC, доходят до этапа преобразования чисел и задействуют новую защиту от исключений. Существующие индексы пакетов, используемые в тестах, остались без изменений.
- **Тесты (`test_conv_to_hrf.py`):** Обновлены с учетом текущего формата CSV (12 полей) и формата вывода `_fmt_dt` (`HH:MM:SS`, `DD.MM.20YY`); исправлена ​​ошибка `NameError`, возникавшая из-за отсутствия импорта функций `to_txt` и `to_compact`; тест `test_csv_format` дополнен полной проверкой структуры CSV на уровне индексов полей. ### Производительность (замеры от 22.09.2026)
- **CPython:** 115 262 пакета/с — в **3,4 раза** быстрее, чем micropyGPS.
- **MicroPython RP2040 @ 133 МГц (режим интерпретатора, без поддержки `@native`):** 486 пакетов/с — в **22,5 раза** быстрее, чем micropyGPS.
- **0 байт** оперативной памяти выделяется в процессе разбора — подтверждает отсутствие выделения памяти в "горячем" пути выполнения (конструкция `try/except` не вызывает выделения памяти при успешном выполнении).


## [2.4.0] - 2026-09-09

### Добавлено
- **Дашборд. Монопольный захват порта:** Внедрена блокировка интерфейса в `_open_serial` для предотвращения конфликтов совместного доступа к устройству.
- **Дашборд. Логирование в curses-консоль:** Добавлен хелпер `show_msg` для корректного отображения строк.

### Исправлено и оптимизировано (MicroPython код)
- **Отложенное (ленивое) выделение памяти:** Создание объектов `memoryview` в парсерах `_parse_rmc` и `_parse_vtg` теперь происходит строго по требованию, разгружая горячий цикл обработки.
- **Копирование буфера:** Оптимизирован механизм копирования данных в `parse_line` с использованием высокопроизводительного `memoryview`.
- **Сканер строк:** В метод `_scan_line` передан явный параметр `packet_len` для точного контроля границ пакета.
- **Оптимизация типов данных:** Внутренний буфер времени `_time_buffer` переведен со стандартного Python-списка (`list`) на быстрый фиксированный массив (`array`).
- **Чистка кода MicroPython:** Удален неиспользуемый импорт декоратора `@viper` для абсолютной чистоты RAM.
- **Стабилизация стека USB-CDC и инициализации:**
  - Переработана логика пробуждения USB-CDC на стороне контроллера (триггер изменен с `0x03` на `0x04`).
  - Добавлено корректное ожидание инициализации устройства `/dev/ttyXXX` на Linux-хостах при подключении платы.
  - Исправлен автозапуск USB-CDC: добавлен обязательный сброс линий DTR/RTS перед их повторным подъемом.
- **Модули времени и RTC:** Исправлена ошибка в методе `get_time` — добавлен вызов `tuple()` для совместимости с `time.mktime`. Сделаны косметические правки в модуле синхронизации аппаратных часов реального времени (`sync_hardware_rtc`).


## [2.3.0] - 2026-08-09

### Добавил
- Lookup-таблицу `_HEX_VALUE` для быстрой проверки CRC
- 24-битные идентификаторы типов сообщений (`_MSG_ID_RMC`, `_MSG_ID_GGA`, `_MSG_ID_VTG`, `_MSG_ID_GLL`)
- 16-битные константы Talker ID для NMEA v4.10+ (`_TALKER_ID_BD`, `_TALKER_ID_QZ`, `_TALKER_ID_IR`)

### Технические детали
- Все декораторы `@native` и `@viper` являются опциональными - код работает в чистом интерпретаторе MicroPython без потери функциональности

### Изменил
- **`parse_line()`**: быстрый фильтр по созвездию и типу сообщения **до** копирования в буфер - отсечение мусорных пакетов
- **`_scan_line()`**: однопроходный сканер с ранним выходом при нахождении `*`, проверка CRC через таблицу HEX
- **`_get_constellation()`**: определение созвездия через lookup-таблицу вместо цикла сравнений
- **`_parse_rmc()`**: локализация `self._comma_pos` в переменную `cp`, убрал повторные attribute lookups
- **`_parse_gga()`**: локализация пере…*: 494 pkt/s при 176 байт RAM на пакет
- **CPython (3.9 GHz)**: 109,453 pkt/s
- **В 22.6 раза быстрее** micropyGPS на RP2040
- **В 2.8 раза быстрее** micropyGPS на CPython
- **В 1.4 раза быстрее** adafruit_gps на CPython
- **В 1.3 раза быстрее** pynmea2 на CPython
- **В 2.1 раза быстрее** pynmeagps на CPython
- **В 1.7 раза быстрее** vihasnaps на CPython
- Удельная эффективность: **27.93 пакетов/MHz** (против 20.18 у adafruit_gps)
- 100% успешно обработанных пакетов в тестах (333,333 из 333,333)

## [2.1.0] - 2026-07-23

### Добавил
- Базовый интерфейс `IGNSSParser` для унификации API всех GNSS-парсеров
- Методы интерфейса: `is_valid()`, `get_constellation()`, `parse_line()`, `reset()`
- Константа `INTERFACE_VERSION = 0b0001_0001` для проверки совместимости
- Экспорт `IGNSSParser` в `__init__.py` для удобства расширения
- Поддержка парсинга координат из GGA через унифицированный метод `_parse_coordinates`

### Изменил
- `NMEAStreamReader` теперь типизирован и использует методы интерфе…акт (добавлены методы-обертки `is_valid()`, `get_constellation()`)
- Упрощена логика `reset()` - единый метод сброса всех состояний
- Улучшена точность бенчмарка памяти: переход с `gc.mem_free()` на `gc.mem_alloc()` для исключения влияния фрагментации кучи

### Производительность
- **23.8x** быстрее micropyGPS на RP2040 (502 pkt/s против 21 pkt/s)

## [2.0.0] - 2026-07-12

### Добавлено
- Поддержка VTG (Track Made Good and Ground Speed)
- Поддержка GLL (Geographic Position)
- Поддержка VTG без Mode Indicator (старый формат NMEA)
- Диагностика по типам сообщений
- Модуль `conv_to_hrf` с функциями форматирования: `_to_txt`, `_to_csv`, `_to_json`, `_to_compact`
- Функция `to_format()` и константы форматов (`FMT_TXT`, `FMT_CSV`, `FMT_JSON`, `FMT_COMPACT`)
- Форматирование времени и даты через `_fmt_dt()` с поддержкой `bytes` и `str`

### Изменено
- `parse_line` разбит на отдельные методы: `_parse_rmc`, `_parse_gga`, `_parse_vtg`, `_parse_gll`
- GLL при статусе 'V' сбрасывает только координаты, не трогая данные из других сообщений
- Один `memoryview` для всех полей GGA (вместо нескольких)
- Сборка CSV-строк переведена на `",".join()` для корректного парсинга в MicroPython
- Все магические строки, числа и идентификаторы вынесены в константы модуля

### Исправлено
- Критическая ошибка `TypeError` при сравнении полей `NoneType` с `int` (HDOP, созвездие, режим фикса) до получения полного пакета GGA
- Ошибка `SyntaxError` в MicroPython при использовании многострочных f-строк
- Ошибка `TypeError: join expects a list of str/bytes` в `_to_csv` (добавлено явное приведение типов)
- Некорректный вывод `None` в текстовых и JSON форматах (теперь возвращаются пустые строки или дефолтные значения)
